02 / 方法与计算流

恢复终点已知，后续只补实际细化的修正

本方法提供的条件

恢复网络先给出完整结果 R。利用既有的一次终点观测，得到各层的恢复 K/V；原生第10步已经提供另一端点。直接恢复区不再产生真实 Wan 更新，参与细化的 token 只在事件触发时产生新的修正。

这些固定端点、固定归属和稀疏修正共同规定了后续上下文的计算形式。原版 Wan 的完整状态每步变化，不能直接套用这项省算而保持其原始算法。

本轮实际减少的工作

旧实现先插值完整上下文，再加修正、覆盖当前 token，随后再次提取端点、插值并写回新修正。新实现按 token 一次完成这些操作，省掉中间张量和多次读写；当前查询位置映射每步建立一次，供30层共用。

仍使用原来的 FlashAttention 和线性层。这是利用恢复轨迹结构的算子与计算流融合；若其他方法也建立同样的固定恢复端点与稀疏修正，它也可迁移，不能据此声称独占的新算法。

每类 token 如何构造当前注意力上下文

先按现有规则计算端点插值 At。直接恢复 token 使用 At；本步未触发的细化 token 使用 At 加最近一次真实修正；本步触发者使用真实 K/V，并记录它与 At 的差。

A_t = BF16(lerp(K_R, K_10, f_t))
未触发：K_t = BF16(A_t + ΔK_last)
已触发：K_t = K_live；ΔK_last ← BF16(K_live − A_t)
V 同样处理；直接恢复区 Δ = 0。

保持原有 BF16 插值、加法和减法的舍入位置。β=.75、τ=.010、恢复权重、选区、逐步事件判断、原生前十步、真实历史 UniPC、第50步融合与最终 VAE 均不变。
